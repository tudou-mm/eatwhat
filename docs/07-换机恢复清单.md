# 换机恢复清单

> 换电脑时照着这份做。**先做「第 0 步」，否则会丢东西。**
> （仓库地址：`https://github.com/tudou-mm/eatwhat`）

---

## 第 0 步 · 换机前在旧电脑上（最重要）

**先把代码推到 GitHub。** `git push` 在本沙箱环境走不通（`github.com` 被代理阻断），
必须用 Git Data API：

```bash
cd <项目根>
export GITHUB_TOKEN=$(gh auth token)      # 需已登录 gh，scope 含 repo
python server/tools/push_via_api.py       # 逐提交重建，sha 与本地一致
python server/tools/push_via_api.py --dry-run   # 先空跑看看
```

推送后**核对**：远端 HEAD 应等于 `git rev-parse HEAD`。

> ⚠️ 只有这两个文件是 `.gitignore` 的，**推送不带它们，换机后必须手动重建**：
> - `assets/data/amap-key.js`（高德 Key，见下方第 3 步）

## 第 3 步 · 重建高德 Key 文件（**别漏，否则地图退化成地标列表**）

新建 `assets/data/amap-key.js`：

```js
window.__EATWHAT_AMAP_CFG__ = {
  keys: ['你的高德Key'],            // 「Web端(JS API)」类型
  securityJsCode: '你的安全密钥',    // 与 Key 是两个不同的值
  restFallback: false
};
```

⚠️ 三个坑（详见 README「配置高德地图 Key」）：
- Key **平台类型必须是「Web端(JS API)」**，选「Web服务」会得到
  「地图好好的，就是拿不到地址」（报 `10009`）
- `securityJsCode` **不是**申请 Key 时填的那个「应用私钥」，填错报 `10008`
- **不配也能跑** —— 自动降级到内置 40 个成都地标列表，坐标仍是真的

## 第 4 步 · 起服务验证

```bash
python dev.py
```

然后浏览器开 `http://127.0.0.1:8080/client/feed.html`，能看到信息流就算成功。

**两个入口**（v1.9 起后端会自己发前端）：
- `http://127.0.0.1:8080/...` —— 推荐，同源无跨域，手机也用这个
- `http://127.0.0.1:5173/...` —— 分离部署，改前端即时刷新，但要跨域

账号：平台端 `admin` / `admin123`；商家端 `13800138000`（登录用短信码，dev 会回显）。

## ⚠️ 换机会丢、需要重建的东西

| 东西 | 会不会丢 | 怎么办 |
|---|---|---|
| 代码 | ✅ GitHub 有就没事 | 见第 0 步 |
| `assets/data/amap-key.js` | ❌ **必丢**（gitignored） | 见第 3 步 |
| `server/uploads/` | ❌ 会丢（gitignored） | 演示数据，可不迁移 |
| JDK / Maven / Python 环境 | ❌ 要重装 | 见第 1 步 |
| **项目记忆与技能**（AI 侧） | ❌ **不在仓库里** | 见下方 |

### 关于「AI 侧的东西」

以下内容**不在 Git 仓库里**，换机后要看情况重建：
- `.workbuddy/memory/` —— 项目记忆（关键决策、踩坑记录）
- 用户级技能（`~/.workbuddy/skills/`）—— 如 `windows-port-process-ops`、
  `chrome-cdp-e2e`、`github-push-via-api`、`safe-site-publish`

**重要决策和踩坑其实都写进 `README.md` 与 `docs/` 了**，那些跟着仓库走，不会丢。
技能可以重装或重建。
