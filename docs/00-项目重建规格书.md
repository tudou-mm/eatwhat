## 0. 一句话定位

本地生活「吃什么」推荐产品。**商户每天只能发布 1 道新菜**（图文或视频二选一），用户在客户端以抖音式全屏滑卡刷「附近今天的新菜」。**不做交易闭环**，到店靠导航 / 电话 / 跳第三方。

## 1. 工程形态

- **纯静态**：HTML + CSS + 原生 JS，**无框架、无构建、无 npm**。
- **三端独立目录**，共用一个后端（后端本期不实现）：

**三个关键算法**（必须照抄，是业务核心）：

```js
// ① 价格自动归档：商家只填价格，档位由平台区间决定
getTierByPrice(price) {
  const p = Number(price);
  if (isNaN(p) || p < 0) return null;
  for (const t of this.priceTiers) if (p >= t.min && p < t.max) return t;
  return this.priceTiers[this.priceTiers.length - 1];
},

// ② 时间衰减：24h 内线性衰减，之后归零（但不物理删除）
timeDecay(publishedAt) {
  const t = new Date(publishedAt.replace(/-/g, '/')).getTime();
  const hours = (Date.now() - t) / 3600000;
  if (hours >= 24) return 0;
  return 1 - hours / 24;
},

// ③ 出流：筛选 + 每店一条 + 排序，全部收敛在这一个方法里。
//    页面只负责渲染 —— 这是保证「筛选页与首页口径一致」的关键。
matchFilter(d, f) {
  if (!d) return false;
  const x = f || this.getFilter();
  if (!this.filterActive(x)) return true;
  const tierOk  = !x.tiers.length  || x.tiers.includes(d.priceTierId);
  const tasteOk = !x.tastes.length || (d.tasteTags || []).some(t => x.tastes.includes(t));
  return tierOk && tasteOk;            // 维度内 OR，维度间 AND
},

buildFeed(tab, filter) {
  const f = filter || this.getFilter();
  const active = this.filterActive(f);

  let pool = this.dishes.filter(d => d.status === 'normal');
  if (active) pool = pool.filter(d => this.matchFilter(d, f));

  // 每店一条：取发布时间最新的那条（筛选态下即"符合条件的最新一条"）
  const byShop = {};
  pool.forEach(d => {
    const cur = byShop[d.shopId];
    if (!cur || this._ts(d.publishedAt) > this._ts(cur.publishedAt)) byShop[d.shopId] = d;
  });
  let items = Object.values(byShop);

  // 内容不足回退（决策 D2）—— 只在未筛选时；筛选态回退会让筛选失效
  if (!active && items.length < 3) { /* 从全量里补"未出现过的店"，见 mock.js */ }

  if (tab === 'random') return 打乱(items);
  return items.sort(/* 置顶 > 权重 > 距离 > 时间衰减 */);
}
```

**筛选条件持久化**：存 `localStorage`，key `clientFilter`，结构
`{ tiers: ['tier_mid'], tastes: ['麻辣'] }`。空数组表示该维度不限；
两维都空则直接删除 key（不留脏状态）。筛选页勾选**实时写入**，
首页出流时读取 —— 这是"筛选完首页跟着变"的全部机制。
`_ts(v)` 是内部时间解析工具，同时兼容 `'yyyy-MM-dd HH:mm'` 字符串与毫秒时间戳。

**排序优先级**：置顶 > 权重 > 距离 > 时间衰减。

## 5. 业务规则（不可违背，用户已逐条冻结）

1. **每店每天默认只能发 1 条**；平台端可覆盖为 `间隔小时 + 日上限`。
2. **规则变更不影响已发记录，从下次算起。**
3. 内容形式 **图文（1-9 图）/ 视频（≤15s ≤20MB）二选一，发布后不可改类型**。
4. **必填**：菜名、店名。**选填**：简介（≤100 字）、价格、视频封面。
5. **店铺审核，菜品不审核**；但菜品要打**真实性标签**（实拍认证 / 广告）并对**价格**做区分。
6. **内容永久不物理删除**。首页靠**时间衰减降权**自然沉底；店铺页永久保留全部菜品。
7. 价位分 **中等 / 高等 / 超高级** 三档，由平台区间自动归档，**商家不可手选**。
8. 筛选维度只有 **价格档 / 口味 / 距离**（距离本期固定"不限"）。**不做搜索**，靠纯随机。
   - 逻辑：维度内 **OR**（多选口味命中任一即可），维度间 **AND**（价格档与口味都要满足）
   - **筛选条件作用于首页信息流**，不只是筛选页：条件存 `localStorage`，
     筛选页勾选**实时同步**，首页顶部出现条件条，可一键清除
   - 筛选态下每店取「符合条件的**最新一条**」（不是笼统的最新一条），**不限 24h**，
     且**禁用**「不足 3 条回退旧内容」—— 回退会把不符合条件的菜塞回来，筛选就失效了
   - 筛选后仍守「每店一条」，与首页既有结构一致
   - **失效条件自动收敛**：平台删掉价格档后用户浏览器里遗留的旧 id 会被自动剔除
     （`sanitizeFilter`，只减不增；数据源为空时跳过校验，避免误清空用户条件）
9. 互动只做 **点赞 / 收藏 / 评论**；分享、导航、电话、跳第三方收进「更多」三级菜单。
10. **打卡用滑动解锁**（不是点赞按钮）——滑动的沉浸感更强。
11. **不做订单 / 交易**。身份是"推荐"，不是"外卖"。
12. 违规处理三级：**内容下架 → 商家禁言 → 封店**；用户侧：**警告 → 限评论 → 封号**，封号保留历史评论。
13. 排序按**地区**处理（本地生活优先）。
14. 推荐排名支持：**拖拽排序、置顶、权重**，且有客户端实时预览。

## 6. 关键交互实现要点

| 功能 | 实现方式 |
|---|---|
| 全屏竖向滑卡（feed） | CSS `scroll-snap-type: y mandatory` + `scroll-snap-align: start` |
| 横向图片轮播（dish） | CSS `scroll-snap-type: x mandatory` + 圆点指示器 + `1/3` 计数 |
| 记录已浏览（随心看排除） | `IntersectionObserver`，`threshold: 0.6`，写入 `S.browsed` |
| 排名拖拽排序 | HTML5 原生拖拽 `dragstart` / `dragover` / `drop` |
| 滑动打卡 | 指针事件 `mousedown`/`touchstart`/`mousemove` 拖 `slide-thumb` 解锁 |
| 打卡持久化 | `localStorage`，key `checkinShops` |
| 登录态持久化 | `localStorage`，key `loggedIn` |
| 未登录拦截 | `requireLogin()` 前置判断，引导去 `login.html` |
| 埋点占位 | 每页统一定义 `function track(event, data) { console.log('[track]', event, data); }` |
| 防 XSS | 用户输入渲染前过 `escapeHtml()` |
| 内容不足回退 | 首页内容 < 3 条时回捞旧内容补位。**仅在未筛选时生效**，筛选态禁用 |
| 筛选条件持久化 | `localStorage`，key `clientFilter`，存 `{ tiers, tastes }`；两维全空则删 key |
| 筛选状态条 | 首页顶部，仅筛选生效时显示；右侧「清除」一键恢复，⚙ 变红 |
| 筛选口径统一 | 筛选页与首页**共用 `MOCK.buildFeed`**，避免两处条数对不上 |
| 返回缓存刷新 | 监听 `pageshow`（`e.persisted`）重读条件重绘 —— 否则改完筛选按返回键首页不变 |
| 价格档变更联动 | `config.html` 保存时遍历 `MOCK.dishes` 重算 `priceTierId` |

**随心看 Tab**：随机排序 + **排除已浏览**。
**附近 Tab**：置顶 > 权重 > 距离 > 时间衰减。
两个 Tab **都受筛选影响** —— 筛选在出流前先过滤候选池。

## 10. 后端工程（S4 已交付）

**位置**：`server/`，Spring Boot 3.2.5 + Java 17 + JPA + Lombok。
默认 **H2 内存库**，`mvn spring-boot:run` 开箱即跑；用 `-Dspring-boot.run.profiles=mysql` 切 MySQL。

**包结构**：
```
com.eatwhat
├── EatWhatApplication.java
├── auth/      JwtUtil(签发/校验) AuthContext(ThreadLocal 身份) AuthInterceptor(统一拦截)
├── common/    R(统一响应) BizException GlobalExceptionHandler Views(视图转换层)
├── config/    CorsConfig WebConfig(装配拦截器+托管 /uploads) DataSeeder
├── entity/    Shop Dish Comment AppUser Report PlatformConfig
├── repository/ 6 个 JpaRepository
├── service/   ConfigService DishService RankService CommentService AppUserService ShopService
└── controller/ CommonController ClientController MerchantController AdminController
                AuthController(登录发证) UploadController(文件上传)
```

**6 张表**：`shop` `dish` `comment` `app_user` `report` `platform_config`（DDL 见 `server/src/main/resources/db/schema.sql`）

**⚠️ `Views.java` —— 三端共用的实体→视图转换层（关键）**

前端读的是**嵌套结构**（`shop.stats.views`、`comment.reply.content`、`user.comments`），
而实体是**扁平字段**（`statViews`、`replyContent`、`commentCount`）。
直接返回实体**不会报错** —— 页面只会静默显示空白/undefined，极难排查。
所以统一收在 `Views.java`，三端共用一份结构定义，字段顺序对齐 `mock.js`。
**新增接口时不要绕过它直接返回实体。**

**业务规则集中在 Service 层**（不要在 Controller 里写业务）：

| 规则 | 位置 |

**前端适配层** `assets/js/api.js`：

- 按 `location.pathname` 识别当前端，只拉对应端的启动聚合接口

**推送到 GitHub**（`push_via_api.py`）：

沙箱/代理环境常**阻断 `github.com:443` 直连**（`git push` 报
`Connection was reset` 或 `Failed to connect to github.com:443`），
但 `api.github.com` 是通的。此时 `git push` 无解，用这个脚本走 REST API
手工重建 `blobs → trees → commits → ref`：

```bash
export GITHUB_TOKEN=$(gh auth token)      # 或有 repo 权限的 PAT
python server/tools/push_via_api.py        # 逐提交重建，作者/时间/message 原样保留
python server/tools/push_via_api.py --dry-run
```

两条**必须守住**的实现细节（都踩过，会静默出错）：

1. **路径解析必须用 `-z`**。git 默认把非 ASCII 路径 C-quote 成
   `"docs/05-\345\220..."`，照原样拿去 `ls-tree` 取不到对象 → **静默漏掉所有中文名文件**，
   推上去看着成功、内容却是旧的。表现为远端 tree sha 和本地对不上。
2. **commit message 必须逐字节原样传**，不能 `.strip()`。
   git 的 commit sha 对 message 敏感，吃掉结尾那个 `\n` 会让每个提交的 sha
   都与本地不同，`refs/remotes/origin/main` 也就写不进去，本地会一直误显示「领先 N 个提交」。

脚本内置**硬校验**：每建完一个 tree 就跟本地 `^{tree}` 比 sha，
不一致立刻中止且**不动远端 ref**（宁可推失败，也不能推一棵残缺的树上去）。

> ⚠️ 受限环境里 `git update-ref refs/remotes/...` 可能**报 exit 0 但不落盘**
> （lock + rename 被拦）。脚本会写后校验，失败则直接写 ref 文件 ——
> 前提是远端 sha 已用 API 核实过，属于「把已确认的远端状态落到本地」。

> 跑 `drive_*.py` 需要 **venv 解释器**
> （`~/.workbuddy/binaries/python/envs/default/Scripts/python.exe`，装了 websocket-client）。
> 内置的 3.13.12 没装，直接用会报「需要 websocket-client」。

> ⚠️ 端到端脚本里的数量断言**一律跟后端实时对比**，不写死具体数字
> （`drive_admin_e2e.py` / `drive_merchant_e2e.py` 的 `api_data()`）。
> 早前写死过「待审核=2」「在营=6」，一改种子数据就红，而且红得没意义。
> ⚠️ **带时间流逝的断言要留容差**：冷却倒计时每秒都在走，
> 拿开场那份快照比会越比越偏（商家端 e2e 踩过，差 13 秒误报）。

## 10.5 上线前加固（已交付）

> 介于 S4（后端）与 S5（试点运营）之间的一次技术补课。

三项都是原型阶段的「明知故犯」，S5 一次性补齐。**新增文件**：

| 文件 | 作用 |
|---|---|
| `auth/JwtUtil.java` | HS256 签发/校验。启动时校验 secret ≥ 32 字节，太短直接启动失败 |
| `auth/AuthContext.java` | ThreadLocal 存登录身份，提供 `assertSelf(shopId)` 越权检查 |
| `auth/AuthInterceptor.java` | 统一拦截：`/api/admin/**`→admin、`/api/merchant/**`→merchant、`/api/upload`→staff |
| `controller/AuthController.java` | `/api/auth/login` 统一发证（admin / merchant） |
| `controller/UploadController.java` | `/api/upload` 四道校验（见下） |
| `config/WebConfig.java` | 装配拦截器 + 把 `./uploads` 托管到 `/uploads/**` |

**四个必须记住的设计点**

1. **`/api/auth/**` 与 `/api/merchant/apply` 必须公开**。前者不公开就是「登录也要先登录」
   死循环，后者不公开则新商家永远提不了入驻申请。
2. **双层越权防护**。URL 层拦一道（商家 token 只能碰自己 shopId，查询参数与路径变量都查），
   Controller 再强制用 token 里的 shopId **覆盖** body 里的值 —— 漏一道就是越权。
3. **HTTP 状态码 = 业务 code**。401 就是 401，不是「HTTP 200 塞 code=401」，
   适配层要靠状态码决定是否踢回登录页（`GlobalExceptionHandler` 返回 `ResponseEntity`）。
4. **上传四道校验**：扩展名白名单 → **魔数（文件头）** → 尺寸上限 → 服务端 UUID 重命名。
   第 2 道最容易被忽略：扩展名和 Content-Type 都由客户端填，只校验它们等于没校验
   （`.png` 改名 + `image/png` 就能把任意内容塞进静态目录）。

**登录与上传写到前端哪**

- `assets/js/api.js` 维护会话（token / role / shopId），每个请求自动带
  `Authorization: Bearer`；遇 401 清会话并引回登录页。
- `MOCK.login(role, account, password)` / `MOCK.logout()` / `MOCK.isLoggedIn()` /
  `MOCK.upload(file)` 四个方法对页面开放。
- **登录页会被适配层跳过启动预加载** —— 那时还没 token，预加载必然 401。
- 后端没启动时 `MOCK.upload` 降级成 `FileReader` → dataURL，原型照样能预览。
