# 「吃什么」后端接口契约 v1.0

> 配套实现：`server/`（Spring Boot 3.2 + JPA）
> 所有接口统一返回 `{ code, msg, data }`，`code === 0` 表示成功。

---

## 通用约定

| 项 | 说明 |
|---|---|
| Base URL | `http://localhost:8080/api` |
| 请求体 | `application/json` |
| 成功 | `{"code":0,"msg":"ok","data":...}` |
| 业务失败 | `{"code":400,"msg":"距上次发布不足 24 小时…","data":null}` |
| 未找到 | `{"code":404,...}` |
| 服务异常 | `{"code":500,...}` |
| 鉴权 | **本期未做**，登录接口返回 mock token，后续接 JWT |
| 跨域 | 已全放开（`CorsConfig`），上线前需收紧 |

## 一、通用

### 健康检查
```
GET /api/health
→ data: "ok"
```

### 客户端登录
```
POST /api/login
body: { "phone": "13800000001", "code": "123456" }
→ data: { user: {...}, token: "..." }
```
> 手机号不存在则自动注册。被封禁账号返回 403。

### 商家端登录（演示）
```
POST /api/merchant/login
body: { "account": "13800138000", "password": "任意" }
→ data: { merchantId, shopId, token }
```

### 平台端登录（演示）
```
POST /api/admin/login
→ data: { adminId, name: "平台运营", role: "super", token }
```

## 二、客户端

### 1. 信息流
```
GET /api/client/feed?tab=nearby|random&city=成都市&browsed=d_001,d_002
→ data: [ dishView, ... ]
```
- `tab=nearby`：按 **置顶 > 权重 > 距离 > 时间衰减** 排序，取每家店铺最新一条
- `tab=random`：随机序 + **排除 `browsed` 中已浏览的**
- 内容不足 3 条时，自动回捞旧内容补位

### 2. 店铺详情
```
GET /api/client/shop/{shopId}
→ data: { ...店铺字段, dishes: [ dishView ] }
```

### 3. 店铺菜品列表
```
GET /api/client/shop/{shopId}/dishes
→ data: [ dishView ]
```

### 4. 菜品详情
```
GET /api/client/dish/{dishId}
→ data: dishView
```

### 5. 评论列表
```
GET /api/client/dish/{dishId}/comments
→ data: [ { id, userId, userName, avatar, content, at, reply: {content,at}|null } ]
```

### 6. 发表评论
```
POST /api/client/dish/{dishId}/comment
body: { "userId": "u_001", "content": "好吃" }
→ data: commentView
```
> 封禁用户返回 403。

### 7. 互动（点赞/收藏/打卡/浏览）
```
POST /api/client/dish/{dishId}/action
body: { "type": "like" | "favorite" | "checkin" | "view" }
→ data: null
```

### 8. 筛选
```
POST /api/client/filter
body: { "tiers": ["tier_mid"], "tastes": ["麻辣"] }
→ data: [ dishView ]
```
> 空数组表示不限。档位与口味之间是 **AND**，维度内部是 **OR**。

### 9. 客户端配置
```
GET /api/client/config
→ data: { priceTiers: [...], tasteTags: [...] }
```

## 三、商家端

### 1. 工作台
```
GET /api/merchant/dashboard/{shopId}
→ data: { shop, canPostToday, cooldownSeconds, intervalHours, dailyLimit, dishes: [...] }
```

### 2. 发布前校验
```
GET /api/merchant/can-publish/{shopId}
→ data: { can: true|false, cooldownSeconds: 54000, status: "normal" }
```

### 3. 发布菜品
```
POST /api/merchant/dish
body: {
  "shopId": "s_001",
  "name": "麻婆豆腐",
  "type": "image",              // image | video，二选一
  "media": ["url1","url2"],
  "cover": "url",
  "desc": "简介≤100字",
  "price": 28,
  "tasteTags": ["麻辣"]
}
→ data: dishView
```
**服务端校验（按顺序）**：
1. 店铺未封禁、未禁言
2. 当日发布数 < `dailyLimit`
3. 距 `lastPublishAt` ≥ `intervalHours` 小时
4. 菜名非空
5. `type` ∈ {image, video}
6. media 非空；image 时 ≤ 9 张
7. 简介 ≤ 100 字
8. **`priceTierId` 由服务端按价格自动归档，客户端传的一律忽略**

### 4. 编辑菜品
```
PUT /api/merchant/dish/{dishId}
body: { name?, desc?, cover?, media?, price?, tasteTags? }
→ data: dishView
```
> 传了 `type` 且与库里不同 → 报错「内容形式发布后不可更改」。
> 改了 `price` → 自动重算 `priceTierId`。

### 5. 我的菜品
```
GET /api/merchant/dishes/{shopId}
```

### 6. 店铺信息
```
GET  /api/merchant/shop/{shopId}
PUT  /api/merchant/shop/{shopId}
body: { name?, cuisine?, intro?, address?, phone?, hours?, cover?, logo? }
```

### 7. 评论管理
```
GET    /api/merchant/comments/{shopId}      # 该店所有菜品下的评论
POST   /api/merchant/comment/{id}/reply     # body: { content }
DELETE /api/merchant/comment/{id}/reply     # 清除回评
```

## 四、平台端

### 数据概览
```
GET /api/admin/overview
→ data: { shopCount, dishCount, userCount, reportPending,
          shopNormal, shopMuted, shopBanned }
```

### 店铺管理
```
GET  /api/admin/shops
POST /api/admin/shop                    # 新增（审核通过后落库）
POST /api/admin/shop/{id}/mute          # 禁言
POST /api/admin/shop/{id}/ban           # 封店
POST /api/admin/shop/{id}/restore       # 解禁/恢复
POST /api/admin/shop/{id}/rule          # body: { intervalHours, dailyLimit }
```

### 推荐排名
```
GET  /api/admin/ranking?city=成都市
→ data: [ shop ]（已按 置顶>权重>距离>衰减 排序）

POST /api/admin/ranking/order
body: { "shopIds": ["s_005","s_001","s_003"] }
→ 按数组顺序重写权重：weight = total - index
```
> 注意：排序时**置顶优先于权重**，所以置顶店即使权重低也会在前。

### 置顶 / 权重
```
POST /api/admin/shop/{id}/pinned    body: { pinned: true }
POST /api/admin/shop/{id}/weight    body: { weight: 88 }
```

### 内容管理
```
GET  /api/admin/contents
→ data: { all: [dish], removed: [dish], reports: [report] }

POST /api/admin/dish/{id}/real-tag  body: { realTag: "real"|"ad"|"pending" }
POST /api/admin/dish/{id}/status    body: { status: "normal"|"removed" }

POST /api/admin/report/{id}/handle  body: { action: "confirmed"|"rejected" }
   confirmed + type=dish    → 自动下架该菜品
   confirmed + type=comment → 自动下架该评论
```

### 用户管理
```
GET  /api/admin/users                 # 按被举报次数倒序
POST /api/admin/user/{id}/status      body: { status: "normal"|"warned"|"banned" }
```
> 被举报次数 ≥ 3 时，`incReport` 会自动将其状态置为 `warned`。
> **封号不删除历史评论**（冻结规则）。

### 平台配置
```
GET  /api/admin/config
→ data: { priceTiers: [...], tasteTags: [...], cuisines: [...] }

POST /api/admin/config/price-tiers
body: { "tiers": [ {"id":"tier_mid","name":"中等","min":0,"max":50}, ... ] }
→ data: { tiers: [...], recalculated: 3 }
```
> **保存后自动重算所有菜品档位**，`recalculated` 是变更数量。
> 区间无上限用 `max: -1` 表示（因为 JSON 无法存 Infinity）。

```
POST /api/admin/config/taste-tags   body: { tags: ["麻辣",...] }
POST /api/admin/config/cuisines     body: { cuisines: ["川菜",...] }
```

## 六、前端接入方式

适配层 `assets/js/api.js` 已注入全部 22 个页面。切换方式：

```js
// 启用后端
localStorage.setItem('useApi', '1');
location.reload();

// 回到本地假数据
localStorage.removeItem('useApi');
location.reload();

// 后端不在 8080 时改地址
localStorage.setItem('apiBase', 'http://192.168.1.10:8080/api');
```

适配层**保持与 `MOCK` 相同的同步函数签名**，所以页面代码无需改动。
后端未启动时自动降级回本地假数据，原型永远能打开。
