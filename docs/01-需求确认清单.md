# 「吃什么」本地生活产品 —— 需求确认清单

> 版本：v1.0（讨论冻结版）
> 日期：2026-09-14
> 状态：需求已闭合，进入原型设计阶段

---

## 一、产品定位

**一句话**：一个本地生活"吃什么"推荐平台。商户每天发布一道新菜（图文或视频），用户在首页刷到附近店铺的今日新菜，决策"去哪吃"。

**核心特征**：
- 内容供给侧是**商户自发**（UGC）
- 消费侧是**信息流推荐**（不做交易闭环）
- 商业逻辑是**给线下店铺引流**，不是外卖平台

**不做的事**（重要边界）：
- ❌ 不做在线支付
- ❌ 不做真实订单系统
- ❌ 不做外卖配送
- ❌ 不做搜索

---

## 二、三端结构

| 端 | 使用者 | 核心职责 | 独立入口 |
|---|---|---|---|
| **客户端** | 普通食客 | 刷菜、看店、互动、到店 | ✅ |
| **商家端** | 商户 | 发布菜品、管理店铺、回评 | ✅ |
| **平台端** | 平台运营 | 审核、排名、规则配置、违规处理 | ✅ |

**架构约定**：三端独立网页，共用一个后端数据源（后端本期不设计，原型用假数据）。

## 三、需求明细（逐条冻结）

### 3.1 账号与准入

| 编号 | 需求 | 结论 |
|---|---|---|
| A1 | 商家准入 | 注册 → **平台审核** → 通过才能发布 |
| A2 | 用户端登录 | **浏览免登录**；点赞/收藏/评论/发布互动才需登录 |
| A3 | 平台端入口 | 独立地址 + 超管账号，与商家端**物理隔离** |
| A4 | 商家多店 | 待定（本期按"一个商家一个店铺"设计，预留多店结构） |

### 3.2 发布规则

| 编号 | 需求 | 结论 |
|---|---|---|
| P1 | 发布频率 | 默认 **每店 24 小时只能发 1 条** |
| P2 | 频率定义 | 按 **上次发布时刻 +24h** 解锁（非自然日） |
| P3 | 内容形式 | **图文 或 视频，二选一**；发布后**不可更改类型** |
| P4 | 图文规格 | **1~9 张图**，至少 1 张 |
| P5 | 视频规格 | **≤15 秒，≤20MB**；封面**选填** |
| P6 | 必填字段 | **店家名称、新菜品名称** |
| P7 | 选填字段 | **简介（≤100 字）**、价格、视频封面 |
| P8 | 发布后编辑 | **可修改文字/图片**（但不可改图文⇄视频类型） |
| P9 | 平台端覆盖 | 平台可单独设置某店：**发布间隔（小时）+ 日上限**，不设则走默认 24h/1 条 |
| P10 | 规则变更生效 | **不影响已发记录，从下次发布算起** |

### 3.3 内容归位与生命周期

| 编号 | 需求 | 结论 |
|---|---|---|
| C1 | 发布去向 | 上**首页** + 进**店铺菜单** |
| C2 | 首页展示 | 只展示**该店最新一条** |
| C3 | 过期行为 | **不从首页物理移除**，留到下次发布才替换（方案 B）|
| C4 | 排序衰减 | 超过 24h 的内容**权重自然衰减到底**，但不删除（解决霸屏）|
| C5 | 店铺页 | 永久保留该店全部菜品 |

### 3.4 排序与推荐

| 编号 | 需求 | 结论 |
|---|---|---|
| R1 | 首页结构 | **双 Tab**：「附近」+「随心看」 |
| R2 | 「附近」算法 | 距离优先 + 时间衰减 |
| R3 | 「随心看」算法 | **随机**，但**排除已浏览过的** |
| R4 | 整体优先级 | **平台置顶 > 推荐权重 > 距离 > 时间** |
| R5 | 排名粒度 | **按地区独立排序**（本地生活，非全国统一序列）|
| R6 | 平台操作 | 可**拖拽调整顺序**、可设**置顶**、可设**权重** |
| R7 | 重复内容 | 随机流排除已浏览 |

### 3.5 筛选

| 编号 | 维度 | 取值 | 交互 |
|---|---|---|---|
| F1 | 价格档 | **平台定义档位**，按商家填写价格**自动归档** | 多选 |
| F2 | 口味 | 平台预设口味标签 | 多选 |
| F3 | 距离 | **本期不设距离范围限制** | — |
| F4 | 筛选逻辑 | 维度**内部 OR**（选 3 个口味命中任一即可）<br>维度**之间 AND**（价格档与口味都要满足） | — |
| F5 | **生效范围** | 筛选条件**作用于首页信息流**，不只是筛选页<br>条件跨页面保留，直到用户主动清除 | — |

**筛选如何作用于首页**（重要，容易做错）：
- 筛选条件存 `localStorage`，筛选页勾选**实时同步**，首页信息流立即跟随变化
- 首页顶部出现**筛选条件条**，可一键清除；右上角 ⚙ 高亮表示"首页被筛过"
- 筛选态下每家店取「**符合条件的最新一条**」，而不是笼统的最新一条
  —— 否则某店最新菜不符合条件就会被整店剔除，哪怕店里更早有符合条件的菜
- 筛选态下**不限 24h**。筛选是用户主动找东西，若只给 24h 内，小众条件会直接筛空
- 筛选态下**不做**「不足 3 条回退旧内容」—— 回退会把不符合条件的菜塞回来，
  筛选就形同虚设。宁可显示空态 + "清除筛选"引导
- 筛选后仍守「每店一条」，与首页既有结构一致

**价格档规则**：
- 平台端设置档位**名称 + 价格区间**（如 中 ¥0-50 / 高 ¥50-150 / 超高 ¥150+）
- 商家端**只填价格数字**，系统自动归入对应档位
- 档位标签必填，**具体价格数字选填**
