# 吃什么 · 本地生活推荐平台

> 商户每天发布一道新菜，用户在客户端刷「附近今天的新菜」。
> **不做交易闭环** —— 身份是「推荐」，不是「外卖」。

---

## 这是什么

一个本地生活「吃什么」推荐产品原型 + 后端工程。

核心机制很克制：**每家店每天只能发 1 条内容**（图文或视频二选一），
用户端以抖音式全屏滑卡浏览。商家发不出海量内容，用户也就不会被信息淹没 ——
"今天这家店在做什么" 是唯一的信息单位。

## 快速开始

### 只看原型（零依赖）

直接用浏览器打开 `index.html`。所有页面跑本地假数据，无需任何环境。

### 连后端跑（推荐）

```bash
python dev.py                # 一键起后端 :8080 + 前端 :5173
```

也可以只要一个：`python dev.py --api-only` / `--web-only`。

手动起后端：

```bash
cd server
mvn spring-boot:run          # 需要 JDK 17 + Maven
```

后端默认用 **H2 内存库**，免安装数据库，启动即有演示数据。

### 怎么切到后端数据

访问页面时地址栏加 `?api=1`：

```
http://127.0.0.1:5173/client/feed.html?api=1
```

切回假数据用 `?api=0`。也可以走控制台：

```js
localStorage.setItem('useApi', '1'); location.reload();
```

适配层 `assets/js/api.js` 保持了与 `mock.js` 完全相同的**同步**函数签名，
所以**三端 22 个页面接入后端时一行代码都不用改**。后端没启动会自动降级回假数据。

### 跑测试

```bash
cd server/tools
python smoke_test.py 8080        # 21 项后端接口冒烟
node test_adapter.cjs            # 18 项适配层行为测试（含后端挂掉的降级路径）
```

## 核心业务规则

1. **每店每 24 小时只能发 1 条**，平台端可单店覆盖（间隔 + 日上限）
2. 图文（1-9 图）/ 视频（≤15s ≤20MB）**二选一，发布后不可改类型**
3. 必填：菜名、店名；选填：简介（≤100 字）、价格、封面
4. **价格档由平台定义区间，商家只填价格，系统自动归档，不可手选**
5. 排序优先级：**置顶 > 权重 > 距离 > 时间衰减**，按地区独立
6. 超 24h 内容权重归零但**不物理删除**（店铺页永久保留）
7. **只审店铺，菜品不审**；菜品可打真实性标签（实拍认证 / 广告）
8. 规则变更**不影响已发记录，从下次发布算起**
9. 不做订单、不做搜索；互动只做点赞 / 收藏 / 评论
10. 违规处理三级：内容下架 → 商家禁言 → 封店；用户侧：警告 → 限评论 → 封号
